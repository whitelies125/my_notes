### 返回值

调用接口获取数据，用着最方便的，就是直接赋值的方式：

```cpp
std::string FindValue(int key);

auto var = FindValue(key);
```
### 失败信息

一些场景中，函数内部的操作是可能失败的，无法保证返回值总是有效的。
对于外部调用方来讲，可能无法分辨返回值的有效性，例如：

```cpp
std::unordered_map<int, std::string> map = {
	{1, "callo"},
};

std::string FindValue(int key) {
    if (auto itor = map.find(key); itor != map.end()) {
	    return itor->second;
    }
    return ""; // 外部无法判断 "" 是有效值还是查找失败的无效值。
}

auto var = FindValue(key);
```

有很多种方式可以处理这种场景，例如：
1. 约定 magic value 作为无效值
	>偶尔会想要返回一个 0 开始的下标/ID，那么magic value一般来说就要设置为 -1，但这样做，函数的返回值类型就要设置为 int，而事实上我的下标/ID 其类型总是非负的unsigned int。为了一个magic value 而破坏类型逻辑是让人不太舒服的。
2. 返回值表示数据有效性，出参接受数据。
3. 抛异常

都很简单明了的，这里不细说。

在 C++17 及之后，我们多了一种可选择的方式：
### C++17 std::optional

```cpp
std::unordered_map<int, std::string> map = {
	{1, "callo"},
};

std::optional<std::string> FindValue(int key) {
    if (auto itor = map.find(key); itor != map.end()) {
	    return itor->second;
    }
    return std::nullopt; // 这是个空的 std::optional 对象
}

auto var = FindValue(key);
if (var.has_value()) {
	// var 数据有效，可以使用
	var.value();
}
```

好吧，其实也没有太大差别。

这和我用：

```cpp
// 返回 pair，first 表示数据有效性，second 接受数据
std::pair<bool, string> FindValue(int key) {
    if (auto itor = map.find(key); itor != map.end()) {
	    return {true, itor->second};
    }
    return {false, ""};
}

auto var = FindValue(key);
if (var.first) {
	var.second;
}
```

真的有很大差距吗......

其实还是有的。
#### 构造

尽管 std::pair\<bool, T\> 可以说是最接近 std::optional\<T\> 的例子。
但仍然有差距啊。这是 C++，扣的就是这一点点差距哈哈哈。

注意到，当查找失败时：
返回 {false, ""} 确实构造了一个空 string。
返回 std::nullopt 构造空的 std::optional\<T\> 时，这里并不涉及 T 的构造。

当然，返回空 std::optional\<T\>时，尽管省去了构造 T 的环节，但并没有省去 T 的内存占用。
其使用的内存空间，仍包括 T。

这个特点其实是因为内部使用 union 来实现的 std::optional\<T\>。

另外就是，用 pair 的语义欠佳。optional 一眼看出来是什么意思。

#### 更多信息

返回 optional 能携带的信息只有 bool 表示的 true 或 false。

一些场景下，我们拥有对函数返回多种失败情况的处理能力，因此需要知晓函数的详细错误信息。

很容易想到，那返回 std::pair\<int, T\> 就好啦。再约定 first = 0 表示 success 可以使用 second，其他值表示错误码。
或者更早期的返回错误码+出参的方式。

当然是可以的。
只是在 C++23 及之后，我们又多了一种可选择的方式：
### C++23 std::expected

模板设计是 std::expected\<T,E\>，成功获得 T，失败获得 E。
携带的信息比 std::optional 要多，这也就有能力支持对返回的错误信息进行不同处理。

```cpp
enum class ErrorCode {
    NOT_FOUND,          // 文件不存在：使用默认配置
    PERMISSION_DENIED,  // 无读取权限：向上层返回错误
    DECODE_FAILED,      // 文件解码失败：向上层返回错误
    UNSUPPORTED_VERSION // 不兼容的配置文件：终止程序
};

std::expected<Config, ErrorCode> LoadFile();

std::expected<Config, ErrorCode> GetConfig()
{
    auto result = LoadFile();
    if (!result) {
	    // 有更多信息，可以对不同错误进行不同处理。
        switch (result.error()) {
	        case ErrorCode::NOT_FOUND:
	            result = Config{}; // 使用默认配置
	            break;
	        case ErrorCode::PERMISSION_DENIED:
	        case ErrorCode::DECODE_FAILED:
		        return result; // 向上层返回错误
	        case ErrorCode::UNSUPPORTED_VERSION:
	            std::terminate(); // 立即终止程序
	    }
    }
    Apply(result); // 应用配置
    return result;
}
```

同样的，走失败路径时，只会有 E 的构造，而不会有 T 的构造。
